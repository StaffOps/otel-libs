# Repo tooling for spec-driven work — requirements

**Status**: Draft (2026-10-28) | **Owner**: repo owner (approved "faça", 2026-10-28)

## Context (evidence from the 0.3 work, 2026-10-27/28)

- The pre-commit reminder hook in `.claude/settings.json` fired on most Bash
  calls (docker runs, smoke runs, `gh`), not only `git commit` — noise that
  trains everyone to ignore it.
- Agents ran `docker builder prune -af`, `compose down -v` and volume removal
  without approval; Docker disk filled three times on a machine shared with
  other projects.
- Spec rules in `specs/README.md` (reversal actions, dated corrections, ADR
  index) were enforced only by review: D1 and D12 drifted from the code and
  were caught late (A13).
- No requirement→test traceability: the Go `NewSlogHandler` R4 gap shipped
  through A5–A10 unnoticed.
- The local runs did not mirror CI: Python 3.13 + lower deps broke on the
  `v0.3.0-rc.1` tag; `docs/site/index.md` must be regenerated by hand.
- Release mechanics were rediscovered by failing: >3 tags per push trigger no
  workflow; rc tags became "Latest"; `.NET` would have been published as 0.3.
- Agent briefs repeated the same constraints (> 20 times) by hand; context was
  lost twice across sessions.

## Requirements

- **RT1 Hook precision** — the commit reminder SHALL fire only for a Bash
  command that runs `git commit` (anywhere in a compound command) and stay
  silent otherwise.
- **RT2 Destructive-command guard** — WHEN a Bash command would delete Docker
  state (`docker … prune`, `docker volume rm|prune`, `docker rmi`,
  `docker image rm|prune`, `docker system prune`, `docker builder prune`,
  `compose … down … -v|--volumes`) or rewrite/remove published git state
  (`git push --force|-f|--force-with-lease`, `git push … :refs/…` or
  `--delete`, `git tag -d`, `git filter-repo`, `git reset --hard`) THEN the
  hook SHALL return `permissionDecision: "ask"` with a reason naming the rule,
  so a human confirms. It SHALL NOT block read-only commands that merely
  mention those words (e.g. `grep prune`).
- **RT3 Session context** — at session start a hook SHALL inject: branch,
  dirty-file count, the open tasks of active specs (unchecked rows/boxes in
  `specs/*/tasks.md` whose spec status is not "Shipped"), and pointers to
  AGENTS.md and the skills. Output ≤ 60 lines; no network.
- **RT4 Spec lint** — `tools/spec_lint.py` SHALL fail when: an ADR file is not
  in the `specs/README.md` index (or vice versa); a `## D…`/`### S-D…`
  decision in an active `design.md` lacks "Reversal action" (reference
  sections exempt by an explicit `(reference)` marker in the heading); a
  `parity/cases.json` `xfail:<task>` names a task id absent from tasks.md or
  marked done; "TBD"/"TODO" appears in an active spec; a "Corrected" note has
  no ISO date.
- **RT5 Traceability** — `tools/trace_matrix.py` SHALL list every requirement id of
  active specs (R*, G*, P*, SR*, RT*) and the tests/parity cases citing it
  (by id in a test name, docstring/comment, or case `requirement` field), and
  SHALL fail on a SHALL-requirement with no citation unless it is listed in an
  allow-list with a reason. Output: Markdown matrix.
- **RT6 Local verify** — `testing/verify.sh` SHALL run, Docker-only and
  sequentially: Go tests (+ext), Python tests on the CI risk corners
  (3.10/lower, 3.13/lower, 3.13/latest), e2e smoke, `mkdocs build --strict`,
  `docs/site/index.md` freshness, spec lint and traceability; print one
  summary; never prune or `down -v`; stop only the services it (or the e2e
  smoke) started.
- **RT7 CI** — CI SHALL run spec lint, traceability and index freshness on
  every PR/push.
- **RT8 Skills** — project skills SHALL exist for: `change-loop` (the AGENTS.md
  loop with brief templates and the standing agent constraints), `release`
  (per-language tags, ≤3 tags per push, pre-release flag, PEP 440, Go
  submodule tags, verify before tagging), `parity-case` (adding/xfailing cases,
  atomic writes).
- **RT9 Refuter agent** — a project subagent `spec-refuter` SHALL carry the
  adversarial role and the standing constraints (read-only, evidence
  file:line, severity scale, no company names).

## Acceptance
- [ ] Each hook pipe-tested with positive and negative inputs; `jq -e` schema check.
- [ ] Lint/trace/verify run green on the current tree (or the allow-list
      documents every pre-existing gap with a reason and owner task).
- [ ] CI job added; skills and agent load (listed by Claude Code).
- [ ] AGENTS.md points to all of it; CHANGELOG Internal entry.

## Out of scope
- Enforcing anything for humans outside Claude Code beyond CI (no git hooks
  installed on clones).
- A company/term deny-list (sensitive by nature; not stored in the repo).
